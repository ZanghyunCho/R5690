# R5691 가상 유지보수통 — 시험 EFU

**실물 부팅·업데이터 수락·카트리지 없는 인쇄/청소는 미검증입니다. 성공이 확인된 설치본으로 안내하지 않습니다.** 이 파일은 EFU 업데이터용 컨테이너이며 SPI 전체 덤프가 아닙니다.

사용자 요청: 외부 폐잉크 호스를 사용하는 R5691에서 유지보수 카트리지 미장착을 정상 상태로 처리하고 여유 공간을 100%로 보고하는 것.

## 새로 확인하고 수정한 경로

- GR controller 상태 API `0x47ca9528`의 opcode `0x30`은 `0x47e186a6`에 상태를 저장합니다. 원본은 입력 2를 이벤트 `0x2010=2`로 전달하며, 원본 상태 consumer는 유지보수통 UI가 참조하는 `0xA7C`의 첫 바이트 bit 7을 세웁니다. 같은 입력이 수정본에서는 정상 값 `0x2010=0`으로 발행되는 것을 API 전체 ARM 실행으로 확인했습니다. 실제 프린터의 신호를 캡처한 것은 아닙니다.
- 조건부 저장 명령 `0x47ca9608`은 해당 항목에서만 0을 저장하도록 바꿨습니다. 상태 getter `0x47ca8080`도 정상 값을 반환합니다.
- 카운터 판정 `0x47c63e0c`은 순정의 정상/100% 응답 생성기 `0x47c68da8`을 호출하고, 가득 차지 않았음을 반환합니다. 큐 응답은 `80 64 00 00 00 00`입니다. 카운터 경로를 정상화한 뒤 보고 프레임 `0xA82=01 01 64`를 확인했습니다.
- 지정한 6개 ARM 명령만 변경했습니다. 순정 GH와 GR 주 프로그램, 기타 구간은 유지했습니다. 다른 오류를 일괄 무시하는 패치는 없습니다. NVRAM 삭제, 누수 센서 변경, 버전 위조는 하지 않았습니다.

## 압축과 교차 검증

새 허프먼 표를 만들지 않았습니다. 순정 토큰을 유지하며, 수정된 바이트 때문에 잘못된 내용을 복사하게 되는 9개 참조를 literal 데이터로 바꿨습니다. 토큰 수는 원본과 같은 255,138개입니다. 제어 프로그램 압축 길이는 539,097 → 539,166바이트입니다.

- 최종 RCX의 허프먼 표 48개 모두 순정과 바이트 단위 일치.
- 원본 ARM 코드가 하드웨어에 쓰는 허프먼 bank 설정도 동일. 원본 ARM header parser 통과.
- IC4의 5개 구간 모두 원본 ARM 토큰 확장 결과와 일치. 허프먼 주변장치는 모의 실행하지 않았습니다.
- 별도 upstream C 해제기로 최종 EFU 안의 16개 구간을 모두 해제했습니다. 15개는 순정 해시와 동일하고 변경 제어 프로그램 1개는 지정한 패치 결과와 일치했습니다.
- 전체 IPL byte-sum/header-bound SHA-1, 별도 도구의 6개 IPL 재계산, ZIP CRC와 재추출 일치 확인.
- 상태 getter 입력 256건, 조건부 setter 120건, 전체 상태 API 7건, 다른 이벤트 28쌍 검증. 설정·큐·알림 등 외부 I/O는 명시적으로 대체했습니다.

## 한계

이 수정은 펌웨어 상태 인터페이스를 가상화합니다. 실제 IC 버스의 모든 읽기·쓰기 트랜잭션을 에뮬레이트하거나 성공을 확인한 것은 아닙니다. 따라서 별도 칩 쓰기 실패·청소·인쇄 시작 단계까지 동작한다는 보장은 없습니다. 전체 부팅 시험도 수행하지 못했습니다. 과거 부팅 실패 사례를 고려해 이번에도 실물 검증과 오프라인 검사 결과를 구분합니다.

순정 ZIP 4개는 저장소의 `firmware/original`에 그대로 있습니다. 삭제 요청된 과거 수정본·덤프·기록은 복원하지 않았습니다. 이 디렉터리는 이번 요청으로 새로 만든 파일만 포함합니다.

파일 해시와 변경 명령·검증 결과는 `SHA256SUMS.txt`, `manifest.json`에 있습니다.
