# R5691 잉크 오류 합산 정상화 — 비교 후보 v3

**사용자 실기 성공 미확인 후보입니다. 남은 오류 문구나 충전 정지를 해결했다고 확인한 파일은 아닙니다.**

사용자는 MB 전용에서도 잉크팩 인식 오류를 보고했습니다. 이어서 v2를 적용하자 CMYK 오류 목록은 사라졌지만 문구가 남았다고 보고했습니다. 문구의 정확한 재확인은 아직 받지 못했습니다. 이 결과와, v2가 내부 잉크 오류 합산을 보존한다는 코드 분석을 근거로 범위를 좁힌 비교 후보를 만들었습니다.

## 변경 범위

- 기존 MB 가상화 6개 명령과 v2의 임시 `0xA80` 정상/잔량 100% 보고를 유지합니다.
- 추가로, 컨트롤러 상태 API의 **파생 잉크 오류 합산 항목 `0x104`**에 전달되는 값의 하위 1바이트만 0으로 처리합니다. 이 항목이 보관하는 캐시 비트는 `0x47E186BC`의 bit 3입니다.
- 원본 잉크 상태·잔량 입력, 색상별 오류 캐시, 칩 읽기/쓰기·응답 검증·상태 전이는 유지합니다. 합산 판정 결과만 정상화합니다.
- 다른 합산 오류 비트는 유지합니다. 일반 Fatal Error 일괄 무시, 누수 센서 변경, NVRAM/Initial Charge 플래그 변경, 펌프 강제 구동, LUT 변경은 포함하지 않습니다.
- 이 변경은 **내부 합산 상태에도 영향을 줍니다. 화면 문구만 숨기는 수정이 아니며**, 충전·동작 조건에 미치는 영향은 실기 미검증입니다.

`0x47CA9478`은 색상 상태 2–7 또는 관련 raw 상태 등의 조건을 합산하여 `0x104`에 전달합니다. 남은 한국어 문구를 고르는 최종 UI 분기와 이 항목의 연결은 아직 확정하지 못했습니다. 따라서 현재 오류의 근본 원인이 밝혀졌다는 뜻은 아닙니다.

## 오프라인 검증

- 원본 API 진입 인자 24건: `0x104` 외 항목 및 상위 문맥 비트 보존.
- 잔량·raw 상태·종류 입력 120건, 색상별 상태 입력 232건: 원본 캐시·이벤트 보존. v2와의 캐시 차이는 합산 bit 3에 한정.
- 다른 합산 비트 12건, 외부 보고 8건, 오류 합산 비교 5건.
- 원래 API의 prologue를 실행하고 원래 본문으로 복귀합니다. v2가 이미 재사용한 비진입 카운터 본문의 남은 공간에 4개 ARM 명령만 추가합니다.
- 순정 허프먼 표를 유지한 인코더 사용. 원본 ARM의 IC4 5개 구간 확장, 전체 IPL 무결성, ZIP CRC 및 재추출을 검사했습니다. 별도 C 해제기의 16개 구간 검증은 `manifest.json`에 기록합니다.
- 실제 프린터, USB 업데이트 수락, 전체 부팅, 인쇄·충전·펌프 동작은 이 환경에서 시험하지 못했습니다.

## 비교 시 확인할 결과

파일은 EFU 업데이터용입니다. 적용 후 NVRAM을 추가로 바꾸거나 Discharge를 반복하지 않고, 먼저 정상 부팅 여부·CMYK 목록·남은 정확한 문구를 확인하는 비교를 위한 후보입니다. 오류 문구가 사라졌다는 사실만으로 물리적인 잉크 충전 완료를 뜻하지 않습니다.

이전에 사용한 MB 전용과 v2 파일은 각각의 디렉터리에 보존되어 있습니다. 해시와 정확한 변경 명령은 `SHA256SUMS.txt`, `manifest.json`을 참조하십시오.
