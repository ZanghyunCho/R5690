# R5691 카트리지 보고 가상화 — 재충전 진단 후보 v2

**실험 후보이며, 실제 재충전 성공이나 이번 정지의 원인이 확인된 수정본은 아닙니다.** 현재 사용자가 실제 잉크 칩을 장착한 상태에서 비교할 목적으로 만들었습니다. IES 센서를 가득 참으로 고정하는 파일이 아닙니다.

v1 사용 중 Adjustment Program에서 Ink Discharge 후 재충전을 실행하면 ‘시작하는 중입니다’가 10분 넘게 지속되고, LED만 점멸하며 펌프·모터 소리가 없다는 후속 보고를 받았습니다. 충전은 `Communication Error`를 반환하지만 정보 읽기는 동작합니다. 이 현상과 v1 사이의 인과관계는 아직 확정되지 않았습니다.

## 수정 범위

- v1의 잉크 원본 snapshot 덮어쓰기, scalar 상태·종류·오류 cache 강제 정상화, 상태 getter 강제 반환을 제거했습니다. 순정에서 시작하므로 v1의 해당 명령들은 원래 코드로 복구됩니다.
- 제어 프로그램의 실제 잉크 입력·cache·상태 전이·원본 보고 버퍼는 유지합니다. 외부 속성 `0xA80`으로 내보내는 48바이트 프레임만 임시 stack 버퍼에 복사하고, 첫 4색 record의 상태·잔량·잔량 상태에 해당하는 세 필드를 정상/100%로 바꿉니다. 그 외 필드와 나머지 4개 record는 보존합니다.
- `0xA80`은 주 프로그램에서도 소비하는 속성입니다. **화면 표시만 바꾸는 패치라고 보장할 수 없으며**, 주 프로그램의 충전 조건에 미치는 영향은 아직 검증되지 않았습니다.
- 사용자 작동 보고가 있었던 가상 유지보수통 v1의 6개 명령은 유지합니다.
- IES 물리 입력, 펌프 구동부, 초기 충전 완료 Flag, EEPROM/NVRAM, LUT, 버전 검사는 변경하지 않습니다.

**기능 차이:** 실제 제어부의 칩·빈 상태·오류 처리가 복원되므로, v1에서 가려졌던 오류가 드러날 수 있고 칩 없이 사용하는 기능이 줄어들 수 있습니다. 기존 가상 카트리지 기능을 모두 유지하면서 충전도 해결했다고 주장하지 않습니다. 사용자의 현재 실제 칩 장착 조건에서 충전 문제를 비교하기 위한 후보입니다.

## 검증

원본 ARM 코드를 이용한 오프라인 검사에서 유지보수통 전용 부모 버전과 비교하여 scalar 입력 180건, 색별 오류/상태 232건, snapshot 45건의 원본 처리 결과가 일치했습니다. 보고 32건에서 원본 버퍼가 보존되고 지정한 출력 필드만 바뀌는 것을 확인했습니다. 그 외 이벤트 28건에서도 해당 출력 필드 외 속성·알림은 보존됐습니다. 임시 버퍼 사용, stack 정렬, 보존 register 및 API 반환값도 검사했습니다. 설정 I/O·큐·외부 API는 모의 처리했으며, 서비스 명령·센서·전체 충전 동작은 에뮬레이트하지 않았습니다.

최종 EFU에서 16개 구간을 별도 C 해제기로 풀어 지정한 결과와 대조했습니다. 48개 순정 허프먼 표를 유지했고, IC4 5개 구간의 원본 ARM 확장, IPL 체크섬·SHA-1, ZIP CRC 및 재추출도 확인했습니다. 순정 GH와 GR 주 프로그램은 변경하지 않았습니다. 실제 장치 부팅과 업데이트 수락은 미검증입니다.

## 사용 전 확인

이 파일은 EFU 업데이터용이며 SPI 전체 덤프가 아닙니다. 초기화 대기 중인 장치에서 정보 읽기가 된다는 이유만으로 업데이트 가능하다고 판단할 수 없습니다. 진행 중인 작업이 종료되고 업데이터가 정상 업데이트 가능 상태로 확인한 경우에만 비교 대상으로 사용하세요. 충전 완료 Flag를 강제로 설정하거나 배출·충전 명령을 반복하는 절차는 포함하지 않습니다.

기존 v1과 순정 파일은 그대로 보존했습니다. 파일 해시, 변경 명령, 검증 결과와 한계는 `SHA256SUMS.txt`, `manifest.json`에 있습니다.
