# v5 초기화 수정 후보본 — 실제 부팅 미검증

[EFU 다운로드](https://media.githubusercontent.com/media/ZanghyunCho/R5690/main/firmware/custom/virtual-csic-t3400-candidate-v5/FWE642TL_GR_VIRTUAL_CSIC_MB_T3400_CLUT_CANDIDATE_v5.EFU)

**v4는 실제 부팅 도중 꺼지는 문제가 보고되어 회수되었습니다. v5는 확인된 코드 결함을 고친 후보본이며, 실제 꺼짐의 직접 원인과 v5의 정상 부팅은 아직 확인하지 못했습니다.**

수정 내용:

- 보호 필드 쓰기가 슬롯 번호 1/2/3을 오류값으로 반환하던 버그를 수정했습니다.
- 초기 필드 쓰기·칩 읽기에 새 속성 요청을 추가하지 않습니다. 활성화 전에는 순정 진입 경로를 유지하고, 원래 슬롯 등록 경계에서 속성 준비를 확인한 뒤 가상 칩을 생성합니다.
- CSIC GPIO 설정·해제와 컨트롤러 하드웨어 초기화를 순정으로 복원했습니다.
- FF 영역에 런타임 상태를 쓰지 않으며, 기존 UID 캐시로 준비 상태를 확인합니다.
- 잉크 100% 보고, 기존 유지보수통 패치와 T3400 공통 모드 CLUT를 유지합니다. 일반 오류·IES·누수 센서·펌프 분기·Initial Charge 플래그·물리 칩 이력 삭제 패치는 포함하지 않습니다.

ARM926 환경에서 초기 필드 쓰기 64개, 반환값 대조 8개, 활성화 전 순정 진입 경로 36개, 순정 전체 스캔 72회, 소비량 기록·재등록 각 144회, 초기 RAM 재구성 4회를 확인했습니다. FF 영역을 읽기/실행 전용으로 둔 상태에서도 통과했습니다.

속성·OS 이벤트·하위 GPIO API는 합성 응답입니다. 프린터 전체 OS·워치독·실제 하드웨어 초기화·물리 부팅·무칩 인쇄·자동 공급은 미검증입니다. 위 결과를 실제 부팅 성공으로 해석하면 안 됩니다.

EFU 14개 레코드 무결성, 5개 CROM 원본 ARM 복원, 독립 IPL 보정, ZIP 재읽기를 검사했습니다. T3400 LUT v1 부모 파일에서 GR 컨트롤러 저장 영역과 무결성 필드만 달라집니다. 상세 결과는 `manifest.json`, 해시는 `SHA256SUMS`에 있습니다.
