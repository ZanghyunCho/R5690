# V8 — 무칩 사용 시 잉크 "부족" 경고 수정 후보

[EFU 다운로드](https://media.githubusercontent.com/media/ZanghyunCho/R5690/claude/friendly-ritchie-8ou26m/firmware/custom/virtual-ink-counter-v8/FWE642TL_GR_VIRTUAL_CSIC_MB_T3400_CLUT_MATTE_SML_INKCOUNT_CANDIDATE_v8.EFU)

SHA256: `84dc8553e9184f4dcaf85425e7518ab737a416d07aa1fa44717b531784b641dc`

V7(= V6 가상 카트리지 + T3400 Enhanced Matte SML) 위에 컨트롤러 수정 하나를 더했습니다.

## 증상과 원인

사용자 보고: V6/V7에서 칩 없이 동작하지만, 잔량 막대가 가득 찬 C에 경고(⚠)가 한 번씩 표시됨.

- 잔량 상태 계산 `0x47C61B24`는 칩이 아니라 프린터의 **색별 누적 사용량 속성 `0x808/0x809/0x80D/0x80E`**를 용량 기준값과 비교해 정상(`0x80`)·부족(`0x83`, 상태 4)·소진(상태 5/6)을 정합니다.
- 이 누적값은 **새 잉크팩 ID가 등록될 때만** 0으로 초기화됩니다(`0x47C58B5C` → `0x47C5BB68(slot,0)`).
- 가상 카트리지는 ID가 고정이므로 초기화가 일어나지 않고 사용량이 계속 쌓입니다. 가장 많이 쓴 C가 먼저 부족 경고에 도달했고, 그대로 두면 **소진 상태로 인쇄가 멈출 수 있었습니다.**
- V6의 잔량 100% 고정은 표시 바이트에만 적용되므로, 막대는 가득 차 있고 경고만 남는 현재 화면과 일치합니다.

## 수정

`0x47C61B24` 안의 누적 사용량 읽기 4개를 0 저장으로 바꿨습니다(제자리 수정, 61바이트, 코드 동굴 없음).

- 잔량 상태 판정만 누적값을 무시합니다. 누적값 기록, 가상 칩 동기화, 다른 함수는 그대로입니다.
- **잉크 센서 플래그 경로 유지**: `0x47C62038`이 센서를 두 번 확인한 뒤 세우는 `0x47D5EE1C` 플래그가 켜지면 원래와 같은 소진 상태(6)가 됩니다.
- 라이브러리, 주 프로그램, 부팅 코드, 화면 버퍼 관련 V6 수정은 V7과 동일합니다.

## 오프라인 검증

원본 상태 계산 함수를 V7/V8 양쪽에서 실행(`tools/validate_virtual_ink_counter.py`, 결과 `docs/virtual-ink-counter-fix.json`):

| 상황 | V7 | V8 |
|---|---|---|
| C 누적값 부족 구간(사진 상황) | C = `0x83` 부족 | 전부 `0x80`, 100% |
| C 누적값 소진 초과 | C 상태 6 | 전부 정상 |
| 센서 플래그 켜짐 | 상태 6 | 상태 6 (동일) |

용량 기준값은 합성 값이며, 속성 읽기·알림 등은 모의 처리했습니다. CROM 재압축(순정 허프먼 표, 토큰 수 동일), 원본 ARM 헤더/LZ 재생 5구간, 14개 레코드 IPL 체크섬·SHA-1, ZIP 재읽기, 별도 추출기로 재해제 일치를 확인했습니다.

## 한계 / 주의

- **실기 미검증**: 업데이트 수락, 부팅, 경고 해소.
- 사용량 기반 잔량 추정이 사라집니다. **잉크팩 잔량은 눈으로 확인하세요.** 빈 팩 감지는 센서 경로에만 의존합니다(센서 정체는 디바운스 동작으로 추정, 하드웨어 추적은 아님).
- 누적값을 쓰는 다른 경로(`0x47C5A488` 레벨 캐시, `0x47D10C88`)는 그대로이며, 사용자에게 보이는 영향은 미확인입니다.
- 별도 `rcx_correct` 교차 검증은 이 환경에 도구가 없어 수행하지 못했습니다.

## 적용

V7과 같은 방식으로 EFU 업데이터를 사용합니다. 문제가 있으면 업데이트 모드에서 V7·V6·순정으로 복원하세요.
경고가 사라지는지 확인하려면 적용 후 전원을 한 번 껐다 켜고 잔량 화면을 확인하세요.

재생성: V7 EFU(LFS)를 받은 상태에서 `python tools/build_virtual_ink_counter_v8_efu.py`.
