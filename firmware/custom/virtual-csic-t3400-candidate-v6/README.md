# V6 — LCD 화면 버퍼와 코드 충돌 수정 후보본

[EFU 다운로드](https://media.githubusercontent.com/media/ZanghyunCho/R5690/main/firmware/custom/virtual-csic-t3400-candidate-v6/FWE642TL_GR_VIRTUAL_CSIC_MB_T3400_CLUT_CANDIDATE_v6.EFU)

V4·V5의 공통 결함을 재현했습니다. 새 코드를 넣었던 `0x47D70000`은 빈 코드 공간이 아니라 480×272×4바이트 LCD 화면 버퍼 `0x47D69594..0x47DE8D94` 안이었습니다. 순정 화면 지우기가 삽입 코드와 테이블을 덮어썼습니다. 그 뒤 패치된 필드 쓰기를 호출하면 V4·V5 모두 제한 명령 수 안에서 반환하지 못했습니다.

V6는 코드와 압축한 메타데이터를 기존 칩 인증·호환성 처리에서 대체되는 코드 영역으로 옮겼습니다. 외부 분기의 내부 진입이 없는지 검사했고, 공개 진입점과 외부 상수 참조는 보존합니다. 잘못된 인증 입력은 명시적 실패를 반환합니다. 새 코드·테이블에서 화면 버퍼를 향하는 분기·주소 상수가 없음을 확인했습니다. 화면 버퍼에 있던 삽입 내용은 순정 바이트로 복원했습니다.

같은 순정 화면 지우기 뒤에 V6의 모든 코드·테이블이 유지되고, 해당 호출이 정상 반환함을 재현했습니다. 화면 지우기 전후를 포함한 전체 스캔 72회·소비량 기록 144회·재등록 144회, 24개 SKU/슬롯의 메타데이터, 초기화·반환값·오류 보고 회귀 검사도 통과했습니다. 메타데이터와 코드 영역은 합성 실행에서 읽기/실행 전용으로 보호했습니다.

기존 잉크 100% 보고·유지보수통 패치·T3400 공통 모드 CLUT와 V5의 초기화·반환값 수정을 유지합니다. 일반 오류·IES·누수 센서·펌프 분기·Initial Charge 플래그·물리 칩 이력 삭제 패치는 포함하지 않습니다.

**화면 버퍼가 코드를 파괴하는 결함과 수정 효과는 원본 ARM 실행으로 확인했습니다. 실제 프린터의 전원 종료 시점·워치독 로그·V6 정상 부팅은 아직 확인하지 못했습니다. 물리 부팅·무칩 인쇄·자동 잉크 공급은 미검증인 후보본입니다.** V4·V5는 계속 회수 상태입니다.

14개 레코드 무결성, 5개 CROM의 원본 ARM 복원, 독립 IPL 보정, ZIP 재읽기와 최종 파일·검증 코드 해시 일치를 확인했습니다. GR 컨트롤러 저장 영역과 무결성 필드만 T3400 LUT V1 부모 파일과 다릅니다. 상세 결과는 `manifest.json`, 파일 해시는 `SHA256SUMS`에 있습니다.
