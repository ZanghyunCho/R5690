# R5691 잉크 4색 + 유지보수통 가상화 — 시험 EFU

**실기 후속 보고: Ink Discharge 후 재충전 시작 중 멈춤 문제가 보고됐습니다.** 사용자는 처음에는 이 버전이 작동한다고 확인했으나, 이후 실제 잉크 칩이 장착된 상태에서 Adjustment Program으로 배출 후 재충전 시 ‘시작하는 중입니다’가 10분 넘게 지속되고 LED만 점멸하며 펌프·모터 소리가 없다고 보고했습니다. 충전 명령은 `Communication Error`를 반환하지만 정보 읽기는 동작합니다. 원인과 패치의 인과관계는 아직 확정되지 않았으며, 재충전용으로 검증된 버전이 아닙니다. 이 환경에서 직접 부팅·인쇄·청소를 시험한 결과도 아닙니다.

사용자가 작동을 확인한 [유지보수통 v1](../virtual-maintenance-box-v1/)의 6개 수정 명령을 그대로 포함하고, 검정·청록·자홍·노랑 잉크의 상태 인터페이스를 추가로 가상화했습니다.

## 동작 범위

- 첫 4개 잉크 슬롯에 대해 정상 장착 상태와 잔량 100%를 보고합니다. 상태 snapshot의 각 3바이트 record는 `80 64 00`으로 정상화합니다.
- 상태 API opcode `0x26`(잔량), `0x27`(raw 상태), `0x28`(종류), `0x29`(색별 오류/상태)의 cache를 일관되게 처리합니다. 앞의 세 scalar 항목은 기존 채널 0..3 범위 검사를 유지합니다. 상태 조회도 같은 4개 채널에 정상 값을 반환하며, 지원하지 않는 채널의 fallback은 유지합니다.
- snapshot 보고뿐 아니라 별도 오류 갱신도 처리합니다. 칩 미인식/빈 상태/오류를 입력한 native ARM 검사에서 대상 상태 cache는 정상으로 유지됩니다.
- 기존 유지보수통의 정상·100% 동작은 포함합니다. 기존 counter 응답의 native 실행 결과도 같음을 확인했습니다.
- 누수 센서나 그 외 fatal error를 일괄 무시하는 패치는 없습니다. NVRAM 삭제나 프린터별 보정 데이터 수정도 하지 않습니다.

## 구현과 검증

유지보수통 v1에서 이미 반환하도록 바꾼 counter 함수의 옛 본문 일부를 새 helper로 사용합니다. 모듈 크기와 실행 주소는 늘리지 않았습니다. controller·주 프로그램·공유 라이브러리에서 이 영역으로 들어가는 외부 ARM branch와 절대 포인터가 없는지 검사했습니다. 동적 분기 전체에 대한 수학적 증명은 아닙니다.

- 잔량/장착/종류 API: 198건.
- 색별 오류/상태 selector의 set/clear: 232건. 실제로 원본 cache가 변하는 경우도 새 cache는 정상인지 검사했습니다.
- 상태 getter: 48건. 지원하지 않는 채널의 fallback 포함.
- 4색 snapshot: 54쌍. record 외 packet 바이트, 해제 처리, stack과 callee-saved registers 보존 확인.
- 유지보수통과 그 외 상태 이벤트: 28쌍 기존 수정본과 동일. 유지보수통 counter의 응답과 반환 ABI도 동일.
- 최종 잉크 상태 프레임에서 첫 4색의 정상 상태/100%/장착 필드 확인.

설정 I/O와 큐·event transport는 명시적으로 대체한 검사입니다. 다른 처리 코어의 실행, 실제 칩 버스와 물리적인 칩 기록 완료는 재현하지 않았습니다.

압축은 **순정 허프먼 표를 그대로 사용**합니다. 토큰 수는 원본과 같은 255,138개이며, 수정 바이트에 영향받는 65개 복사 참조를 literal로 전환했습니다. controller segment 크기는 539,097 → 539,324바이트입니다.

- 최종 RCX의 48개 허프먼 표 모두 순정과 동일.
- IC4의 5개 구간에서 원본 ARM header parser와 하드웨어 DHT 설정 경로 통과, 원본과 같은 table bank 입력 확인.
- 같은 5개 구간의 원본 ARM 토큰 확장 결과 일치. 허프먼 주변장치 동작 자체는 에뮬레이트하지 않았습니다.
- 별도 C 해제기로 최종 EFU의 CROM 구간 16개 모두 재검사. 변경된 GR controller만 지정한 결과와 일치하고 나머지 15개는 순정과 동일.
- IPL 체크섬·존재하는 header-bound SHA-1, 독립 도구의 6개 IPL 재계산, ZIP CRC와 재추출 일치 확인.

## 파일과 한계

이 EFU에는 잉크와 유지보수통 가상화가 함께 들어 있습니다. 원본 GH와 GR 주 프로그램은 유지합니다. 버전 정보는 위조하지 않았고, 실제 업데이터 수락 여부는 시험하지 못했습니다. EFU는 업데이터 컨테이너이며 SPI 칩 전체 덤프가 아닙니다.

이 구현은 펌웨어의 상태 경로를 가상화합니다. 칩 ID·인증 암호 응답 및 모든 실제 읽기/쓰기 트랜잭션을 에뮬레이트한 것은 아닙니다. 따라서 실제 칩 미장착 상태의 인쇄 시작, 인쇄 중 기록 실패와 청소 완료까지 동작하는지는 실물 확인이 남아 있습니다. 이전 유지보수통 시험본의 사용자 성공 보고가 이번 잉크 확장의 실물 성공을 뜻하지는 않습니다.

파일 해시와 변경 위치·검증 요약은 `SHA256SUMS.txt`, `manifest.json`에 있습니다. 순정 ZIP 4개와 사용자가 작동을 확인한 유지보수통 v1 파일은 그대로 보존했습니다.
