# IC3 추출 EEPROM — Initial Charge Flag ON

사용자 요청에 따라 `IC3_BMAP_ACTIVE.eep`에서 **Initial Charge Flag만 1로 설정한 2,048바이트 파일**입니다. 장치에 쓰거나 충전을 실행한 결과는 아닙니다.

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| EEPROM 논리 `0x0000` 바이트 | `0x00` | `0x01` |
| Initial Charge Flag: bit 0, 논리 ID `0xF7` | 0 | 1 |
| Cleaning Flag: bit 5, 논리 ID `0xF5` | 0 | 0 |

다른 2,047바이트는 추출 원본과 같습니다. 원본 `.eep`와 IC3 덤프는 보존했습니다. 근거는 첨부 Adjustment Program의 `Set initial charge flag` 설정과 모델별 EEPROM 항목표입니다. 프로그램은 이 항목을 **다음 전원 투입 시 초기 잉크 충전을 시작하는 Flag**로 설명합니다. 충전 완료를 위조하거나 IES를 가득 참으로 바꾸는 항목이 아닙니다.

## 적용 대상

지원되는 개별 Flag 쓰기에서 **논리 항목 `0xF7`를 설정**하는 것이 목적입니다. 현재 장치 값을 기준으로는 EEPROM 논리 바이트 0을 읽고 `현재값 | 0x01`로 쓰면 다른 비트를 보존할 수 있습니다. 장치에 실제 적용한 뒤 다시 읽은 값에서 bit 0이 1인지 확인해야 합니다.

이 파일은 IC3 파일 `0xFDE830–0xFDF02F`에서 추출한 스냅샷을 바탕으로 했습니다. 이전 서비스 백업과는 242바이트 다르고 실제 채취 시점은 미확인이므로, 이 파일 전체를 현재 상태보다 최신이라고 간주하면 안 됩니다. 전체 Data Copy 복원은 다른 EEPROM 항목에 기본값을 적용하거나 대상을 걸러낼 수 있어 개별 Flag 쓰기와 동일하지 않습니다.

EEPROM 논리 주소 `0x0000`은 **IC3 SPI 물리 오프셋 0이 아닙니다.** 이 파일은 전체 SPI 이미지나 EFU가 아니며, IC3 BMAP 헤더·사본 상태·다른 NVRAM 구역을 직접 수정한 파일도 아닙니다.

초기 충전이 실제로 시작되는지, 카트리지 설치 오류가 해소되는지는 아직 미검증입니다. 파일 해시와 변경 내용은 `SHA256SUMS.txt`, `manifest.json`에 있습니다.
