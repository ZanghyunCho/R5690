# EEPROM 논리 ID별 기능 대응표

## 주소와 ID 구분

- `0xF7`은 서비스 프로그램의 논리 **항목 ID**입니다. `.eep` 파일의 오프셋 `0xF7`이라는 뜻이 아닙니다.
- Initial Charge 항목 `ID 0xF7`은 EEPROM **주소 0x0000의 bit 0**에 대응합니다.
- EEPROM 바이트 주소는 `.eep` 내부 오프셋입니다. 이번 IC3 유효 사본의 실제 위치는 `0xFDE830 + EEPROM 주소`입니다.
- 여러 ID가 같은 바이트의 전체 또는 일부 비트를 가리킬 수 있습니다. 같은 주소가 반복돼도 오류가 아닙니다.

## 확인 수준

- `named_action`: 프로그램이 이름을 붙인 Flag 설정/해제 동작과 연결됨.
- `traced_reader`: 명시적인 읽기 코드를 대조함.
- `model_setting_binding`: 해당 모델 설정표에서 조정 메뉴·세부 라벨·ID가 연결됨. 실제 실행 및 보정 단위·부호까지 검증했다는 뜻은 아님.
- `usage_only`: 어떤 작업에서 읽거나 쓰는지는 확인했으나, 그 값의 독립적인 제품상 의미는 미확인.
- `container_only`: 알려진 비트가 들어 있는 바이트 전체. 나머지 비트 의미는 미확인.
- `unresolved`: 주소와 마스크는 매핑됐지만 기능명은 아직 확인하지 못함.

총 115개 ID: {'usage_only': 12, 'unresolved': 59, 'container_only': 2, 'model_setting_binding': 39, 'traced_reader': 1, 'named_action': 2}. 모든 기능명을 해독한 표라고 주장하지 않습니다.

## 현재 문제에서 중요한 새 확인

논리 `0x261` → EEPROM `0x0005`, 마스크 `0xFF`는 프로그램의 **Ink leak error reset** 메뉴가 다루는 대상입니다. IC3 추출본에는 `03`, 이전 서비스 백업에는 `00`이 있습니다. `03`의 개별 비트나 실제 오류 판정상의 뜻, 이 값이 현재 설치 오류를 직접 일으킨다는 인과관계는 아직 확인하지 못했습니다. IES(Ink End Sensor)의 실시간 신호라고도 단정하지 않습니다.

Initial Charge ON 파일은 IC3 추출본에서 bit 0만 바꾸었으므로 이 주소의 `03`을 그대로 보존합니다. 두 스냅샷은 242바이트가 다르고 채취 시점은 미확인입니다. 현재 장치의 다른 값까지 바꾸려는 목적이 아니라면 개별 논리 항목 쓰기와 전체 스냅샷 복원을 구분해야 합니다. 여기서는 추가 EEPROM 값을 변경하지 않았습니다.

## 중요한 중복 주소

- EEPROM `0x0000`: `0xEC`은 바이트 전체, `0xF7`은 마스크 `0x01`, `0xF5`는 마스크 `0x20`입니다.
- EEPROM `0x0039`: `0x04`는 바이트 전체, `0x05`는 마스크 `0x01`입니다. 실제 기능은 미확인입니다.
- EEPROM `0x004E`: `0x07`은 바이트 전체, `0xE9`는 마스크 `0x07`입니다. 실제 기능은 미확인입니다.
- EEPROM `0x004F`: `0x08`은 바이트 전체, `0x259`와 `0x25A`는 같은 마스크 `0x03`을 사용합니다. BAM 옵션의 ON 설정값이 각각 1/2이므로 두 독립적인 Flag로 취급하지 않습니다.

## 출하 설정으로만 확인된 항목

`0xC9`, `0xCB–0xCE`, `0x15F`, `0x168–0x16C`는 Shipping setting의 0 쓰기 대상입니다. 이 근거만으로 잉크 잔량·IES·청소 횟수라고 부르지 않습니다. Shipping setting은 Cleaning 항목 `0xF5`에도 값을 씁니다.

## 출처 및 한계

- 모델별 주소/마스크: `EEPROM_LOGICAL_ITEMS.json`과 프로그램 descriptor `0x6969E0`.
- 조정 메뉴명: 모델의 항목 목록 `0x69C150`, 설정 record `0x698540`부터 113개, 각 0x78바이트.
- Ink leak error reset: 메뉴 group `0x81`과 설정 record 44의 논리 파라미터 `0x261`.
- 누수 상태, IES 상태, 카트리지 인식·충전 상태를 동일시하지 않았습니다. 원인 확정이나 장치 동작 시험 결과도 아닙니다.
- 의미가 확인되지 않은 `0x201–0x239` 등의 ID는 숫자가 연속한다는 이유만으로 Head ID, 잉크량, 센서값이라고 추정하지 않았습니다.
