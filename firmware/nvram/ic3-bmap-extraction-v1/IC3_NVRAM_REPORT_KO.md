# IC3 NVRAM 분석 — 0부터 F까지

## 핵심 결과

- IC3에 실제 NVRAM 저장 영역이 확인됩니다. `BMAP0001` 사본은 `0xFD0000`, `0xFE0000`에 있습니다.
- 유효 상태 `0x3F`인 항목은 FD 구역 29번 하나입니다. 순정 참조 ARM 선택 루틴의 제한 실행에서도 29번이 선택됐습니다.
- 추출 EEPROM은 `0xFDE830–0xFDF02F`, 2,048바이트입니다. 원본 그대로 추출했으며 초기 충전·청소 예약 Flag는 모두 0입니다.
- 이전 `bkupdata.eep`와 242바이트 다릅니다. 두 파일의 실제 채취 시점은 확인되지 않았으므로 어느 쪽이 더 최신인지 단정하지 않습니다.
- 앞서 제공한 청소 예약 Flag 해제가 오류를 해결하지 못했다는 사용자 보고가 있습니다. 이번 덤프에서는 이미 0이므로 같은 비트를 다시 지우는 후보는 만들지 않았습니다.
- **IES의 빈 상태가 저장되는 정확한 필드, 설치 오류의 원인, 모든 바이트의 업무상 의미는 아직 확인되지 않았습니다.** 알 수 없는 필드를 임의로 잉크량·센서값이라고 명명하지 않습니다.

## IC3 전체 주소: 상위 16진수 0–F

주소는 16MiB `IC3.bin` 파일의 물리 오프셋입니다. 이 표의 0–F는 각 1MiB 범위를 뜻합니다. EEPROM 논리 주소와 혼동하면 안 됩니다.

| 상위 자리 | IC3 파일 범위 | 확인된 내용 |
|---|---|---|
| 0 | `0x000000–0x0FFFFF` | 부트/코드 및 압축 펌웨어 구간. 0x00DB20의 BMAP0001은 형식명 상수이며 활성 EEPROM payload가 아님 |
| 1 | `0x100000–0x1FFFFF` | 펌웨어/코드 영역; 이 분석에서 NVRAM 삭제 대상으로 지정하지 않음 |
| 2 | `0x200000–0x2FFFFF` | 펌웨어/코드 영역; 이 분석에서 NVRAM 삭제 대상으로 지정하지 않음 |
| 3 | `0x300000–0x3FFFFF` | 펌웨어/코드 영역; 이 분석에서 NVRAM 삭제 대상으로 지정하지 않음 |
| 4 | `0x400000–0x4FFFFF` | 펌웨어/코드 영역; 이 분석에서 NVRAM 삭제 대상으로 지정하지 않음 |
| 5 | `0x500000–0x5FFFFF` | 펌웨어/코드 영역; 이 분석에서 NVRAM 삭제 대상으로 지정하지 않음 |
| 6 | `0x600000–0x6FFFFF` | 0x600000–0x6EFFFF 펌웨어 쪽 구간; 0x6F0000부터 INC_P001 저장 구역; INC_P001: 1개 64KiB sector |
| 7 | `0x700000–0x7FFFFF` | INC_P001: 1개 64KiB sector; NO_ASCII_TAG: 7개 64KiB sector; ADDL0002: 8개 64KiB sector |
| 8 | `0x800000–0x8FFFFF` | NO_ASCII_TAG: 5개 64KiB sector; ADDL0002: 11개 64KiB sector |
| 9 | `0x900000–0x9FFFFF` | NO_ASCII_TAG: 4개 64KiB sector; ADDL0002: 12개 64KiB sector |
| A | `0xA00000–0xAFFFFF` | ADDL0002: 10개 64KiB sector; NO_ASCII_TAG: 6개 64KiB sector |
| B | `0xB00000–0xBFFFFF` | ADDL0002: 12개 64KiB sector; NO_ASCII_TAG: 4개 64KiB sector |
| C | `0xC00000–0xCFFFFF` | ADDL0002: 1개 64KiB sector; NO_ASCII_TAG: 15개 64KiB sector |
| D | `0xD00000–0xDFFFFF` | NO_ASCII_TAG: 4개 64KiB sector; INC_F013: 12개 64KiB sector |

| F | `0xF00000–0xFFFFFF` | INC_A002: 2개 64KiB sector; INC_C006: 6개 64KiB sector; INC_F013: 4개 64KiB sector; 1WAY0001: 2개 64KiB sector; BMAP0001: 2개 64KiB sector |

## NVRAM 저장 형식과 범위

관측한 NVRAM 구간은 `0x6F0000–0xFFFFFF`이고, 64KiB sector 145개입니다. 순정 쓰기/지우기 함수의 허용 범위 검사도 이 IC3 오프셋 범위와 맞는 구간을 포함합니다. 구조를 확인한 것이며 전체를 지워도 된다는 뜻은 아닙니다.

| 형식명 | Sector 수 | 확인 범위 / 미확인 사항 |
|---|---:|---|
| `INC_P001` | 2 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `NO_ASCII_TAG` | 45 | 선두 12바이트가 0인 사례 등. 데이터가 남아 있어 빈 공간이나 고장으로 단정할 수 없음 |
| `ADDL0002` | 54 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `INC_F013` | 22 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `INC_S002` | 6 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `INC_A002` | 6 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `INC_C006` | 6 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `1WAY0001` | 2 | 형식명과 저장 위치 확인. 실제 제품 기능별 필드 의미는 아직 미확인 |
| `BMAP0001` | 2 | 현재 서비스 EEPROM 2KB 이미지의 반복 사본과 유효 상태 표 확인 |

전체 145개 sector의 주소·16바이트 헤더·해시·FF/00 개수는 `IC3_NV_SECTORS.csv`에 있습니다.

## BMAP0001 헤더와 사본 선택

| 상대 오프셋 | 길이 | 이번 FD 구역 값 | 확인된 의미 |
|---|---:|---|---|
| `+0x00` | 8 | `BMAP0001` | 저장 형식 표식 |
| `+0x08` | 2 | `FF 33` (FE는 `FF 7F`) | 순정 구역 선택 코드가 상태값으로 구분. 전체 비트 의미는 미확인 |
| `+0x0A` | 2 | `FF FF` | 의미 미확인 |
| `+0x0C` | 4 | `44 06 00 00` = `0x644` | 헤더 필드. 세대/CRC/길이라고 임의 단정하지 않음 |
| `+0x10…+0x2E` | 31 | `00`×29, `3F`, `FF` | 31개 완전한 payload 위치에 대응하는 상태. 선택 루틴은 `3F`인 항목을 고름 |
| `+0x2F` | 1 | `FF` | payload 앞 정렬/여유 위치로 관측; 별도 의미 미확인 |
| `+0x30`부터 | 각 `0x800` | 2KB 사본 반복 | 데이터 위치식: `sector + 0x30 + index × 0x800` |

FD의 0–28번은 상태 `0x00`, 29번은 `0x3F`, 30번은 `0xFF`입니다. FE에는 `0x3F`인 항목이 없습니다. 단순히 가장 뒤의 데이터를 선택한 것이 아니라 상태 표와 순정 참조 선택 루틴을 대조했습니다. 헤더를 `.eep`에 포함하지 않습니다.

참조 ARM 함수 `0x47C957EC` 실행에서 flash 읽기만 덤프 바이트 복사로 대체했습니다. 장치 전체 부팅이나 설치된 펌웨어의 실시간 실행 결과는 아닙니다. `BMAP_RECORDS.json`에 모든 사본과 이전 백업과의 차이가 있습니다.

## EEPROM에서 의미까지 확인한 항목

| EEPROM 논리 주소 | IC3 활성 데이터 주소 | 값 | 의미 / 근거 |
|---|---|---|---|
| `0x0000` bit 0 | `0xFDE830` bit 0 | 0 | Initial charge flag, 논리 ID `0xF7`, 마스크 `0x01` |
| `0x0000` bit 5 | `0xFDE830` bit 5 | 0 | Cleaning flag, 논리 ID `0xF5`, 마스크 `0x20` |
| `0x0000` 기타 비트 | `0xFDE830` | 현재 전부 0 | 개별 비트 의미 미확인. IES 비트라고 지정하지 않음 |
| `0x0644–0x064D` | `0xFDEE74–0xFDEE7D` | `W9VY010556` | 제품 시리얼 10자. Adjustment Program 논리 ID `0xD1`, 읽기 함수 `0x4091E5`에서 10바이트 읽음 |
| `0x064E` | `0xFDEE7E` | `0x60` | 시리얼 뒤 바이트. 표시 시리얼의 일부가 아니며 체크섬 등으로 단정하지 않음 |

위 항목들은 프로그램의 모델별 항목표와 관련 코드를 대조했습니다. 이전 `.eep`에서도 같은 시리얼이 확인됩니다. `0x644`라는 EEPROM 주소와 BMAP 헤더 `+0x0C`의 값이 같다는 사실만으로 둘을 연결하지 않았습니다.

## EEPROM 논리 주소 전체: 00–0F 열

`EEPROM_HEX_00_TO_0F.txt`는 논리 주소 `0x0000–0x07FF` 전부를 16바이트씩 표시합니다. 각 행의 주소에 열 `00–0F`를 더하면 실제 논리 주소가 됩니다. 해당 바이트의 IC3 물리 주소는 `0xFDE830 + 논리 주소`입니다.

`EEPROM_ALL_2048_BYTES.csv`에는 2,048개 바이트 전부의 원시값, ASCII, 물리 주소, 이전 백업값, 변경 여부, 서비스 논리 ID/마스크, 복원 정책을 적었습니다. 항목 시작 주소 133곳과 고유 논리 ID 115개가 서비스 표에서 확인됐습니다. 항목표에 없다고 사용하지 않는 바이트라는 뜻은 아닙니다.

논리 ID/마스크가 매핑됐다는 것과 실제 센서·카운터의 의미를 안다는 것은 다릅니다. 의미를 확인하지 못한 행은 명시적으로 미확인으로 표시했습니다. `EEPROM_LOGICAL_ITEMS.json`은 프로그램의 원본 descriptor 주소와 마스크를 포함합니다.

아래는 프로그램 Data Copy 복원 코드가 처리하는 정책입니다. 제품 동작상의 의미와는 다릅니다.

## 추가 NVRAM 객체 표

`STOCK_NV_OBJECTS.csv`에는 순정 참조 제어 프로그램의 객체 103개를 숫자 ID·크기·속성 원시값으로 나열했습니다. 크기는 원본 조회 함수 `0x47C98F40`의 방식대로 읽었습니다. 각 객체가 IES, 잉크량, 인쇄 횟수 중 무엇인지 대부분 확인되지 않았으므로 이름을 만들어 붙이지 않았습니다.

## 현재 증상에 대한 결론과 한계

- IC3에서 EEPROM에 대응하는 데이터를 실제로 추출했습니다. 기존의 위치 미확인 상태에서 한 단계 확인된 것입니다.
- 이번 유효 사본의 초기 충전/청소 예약 비트는 모두 0입니다. 같은 Flag를 추가로 지우는 것으로 현재 상태를 바꿀 수 없습니다.
- MB 전용 펌웨어에서도 설치 오류가 나온다는 사용자 보고는 잉크 v1 패치만을 단독 원인으로 단정하지 못하게 합니다.
- 공급관과 IES를 물리적으로 채웠다는 것만으로 전기적 센서 읽기나 카트리지 상태가 정상으로 확인된 것은 아닙니다. 어느 입력이 오류를 만드는지는 별도 추적이 필요합니다.
- BMAP 외 INC/ADDL/1WAY 구역에도 데이터가 있으나, 그 안에서 IES 관련 영구 상태를 특정하지 못했습니다. 전체 NVRAM 삭제는 근거 있는 수정이 아닙니다.
- 파일 채취 시점과 실시간 장치 상태를 모르므로 이전 백업과의 242바이트 차이를 고장이나 새 변경으로 단정하지 않습니다.
- IC3 덤프는 보존했으며 어떤 SPI/EEPROM 데이터도 장치에 쓰지 않았습니다.
