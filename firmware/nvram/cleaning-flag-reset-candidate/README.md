# R5691 EEPROM 청소 예약 Flag 해제 후보

**후속 결과:** 사용자는 이 후보를 적용해도 증상이 바뀌지 않았다고 보고했습니다. 새 IC3 덤프에서 추출한 유효 BMAP 사본에는 초기 충전·청소 예약 Flag가 모두 0입니다. 두 백업의 실제 채취 시점은 미확인이며, 이 후보를 오류 해결본으로 간주하지 않습니다. 새 추출과 상세 주소표는 `../ic3-bmap-extraction-v1/`에 있습니다.

사용자가 제공한 `bkupdata.eep`는 2,048바이트입니다. 원본 SHA256은 `4a23b01db59e307a134da0c5488230c08194c9bb3c5b9ab3203a15a8281f88e5`이며 원본 파일은 변경하지 않았습니다.

첨부 Adjustment Program의 모델 항목표와 read-modify-write 코드를 대조한 결과입니다.

| 항목 | 서비스 논리 ID | EEPROM 논리 바이트 | 비트 마스크 | 백업 값 |
|---|---|---|---|---|
| Initial charge flag | `0xF7` | `0x0000` | `0x01` | 0 |
| Cleaning flag | `0xF5` | `0x0000` | `0x20` | 1 |

프로그램의 `Set cleaning flag`는 논리 항목 `0xF5`를 설정합니다. `Reset the flags` 설정에는 `0xF7=0`과 `0xF5=0`이 포함됩니다. 서비스 쓰기 코드는 원래 바이트를 읽어 항목의 마스크에 해당하는 비트만 갱신합니다.

`bkupdata.CLEAR_CLEANING_FLAG.eep`는 **파일 오프셋 `0x0000`의 `0x20`을 `0x00`으로 변경한 후보**입니다. 변경된 비트는 bit 5 하나이며, 초기 충전 Flag는 원래부터 0인 상태를 그대로 유지합니다. 나머지 2,047바이트는 원본과 일치합니다. IES 상태 Flag를 특정하거나 삭제한 파일이 아닙니다. 이 비트가 현재 설치 오류의 원인이라는 실기 증거는 아직 없습니다.

## 적용 범위

대상은 EEPROM **논리 항목 `0xF5`에 0을 쓰는 작업**입니다. 현재 장치 값을 기준으로 한 바이트 연산은 `현재값 & 0xDF`입니다. 백업 당시 값 `0x20`에는 결과가 `0x00`이지만, 이후 다른 비트가 바뀌었다면 그 비트는 보존해야 합니다.

이 주소는 **IC3 SPI 파일 오프셋 0이 아닙니다.** IC3에 직접 같은 주소로 쓰는 용도로 사용하지 마세요. 실제 물리 칩 위치는 아직 확인하지 않았습니다.

프로그램의 EEPROM Data Copy 복원 경로는 이 바이트를 파일에서 가져오는 항목으로 처리하지만, 동시에 다른 EEPROM 바이트에는 모델 기본값을 적용하거나 복원 대상을 걸러낼 수 있습니다. 따라서 **한 Flag만 바꾸려는 목적으로 전체 초기화나 전체 Data Copy 복원을 실행하는 것과는 구별해야 합니다.** 지원되는 개별 Flag/바이트 쓰기를 우선 사용하고, 수정 `.eep`는 그 변경 내용을 담은 비교·적용 후보로 보관하세요. 장치 적용 후 다시 읽은 값에서 bit 5가 0인지 확인해야 실제 쓰기 성공을 알 수 있습니다.

이 환경에서는 장치에 쓰거나 충전·부팅·인쇄를 실행하지 않았습니다. 이 파일은 EFU 또는 전체 SPI 덤프도 아닙니다. 해시와 근거 주소는 `manifest.json`, `SHA256SUMS.txt`에 있습니다.
