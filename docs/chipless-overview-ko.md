# R5691(R5690 시리즈) 무칩 동작 — 전체 과정 정리

이 문서는 순정 펌웨어 `FWE642TL`에서 출발해 칩 없이 동작하는 가상 카트리지 펌웨어(V6 → V8)에 이르기까지의 과정을 요약합니다.
상세 근거는 각 단계에 연결된 문서와 `firmware/custom/*/manifest.json`에 있습니다.

> 실기 확인과 오프라인(에뮬레이터) 확인을 구분합니다. 별도 표시가 없으면 오프라인 결과입니다.

---

## 0. 기반 작업: 펌웨어를 풀고 다시 묶기

```
EFU (ZIP)
 └─ FWE642TL.rcx
     ├─ IPL 블록 8개, 레코드 14개 (GH/GR 두 보드용)
     │   └─ SPI ROM 이미지
     │       └─ CROM 압축 구간 (주 프로그램, 라이브러리, 컨트롤러 …)
     └─ 레코드마다 16비트 체크섬과 SHA-1
```

- **CROM 압축**: 허프먼과 LZ를 섞은 Epson 고유 형식입니다. 허프먼 표는 하드웨어 디코더에 그대로 올라가므로 새 표를 만들지 않습니다. 순정 표와 토큰을 유지하고, 수정 때문에 깨지는 복사 참조만 원본 문자(literal)로 바꾸는 재압축기를 사용합니다(`tools/stock_crom_codec.py`의 `repair`).
- **무결성**: 레코드마다 바이트 합과 SHA-1을 다시 계산하고, 14개 레코드 전체를 다시 검사합니다.
- **검증 방식**: 프린터에 직접 접근할 수 없어서, 펌웨어의 원본 ARM 코드를 Unicorn 에뮬레이터로 실행해 패치 전후 동작을 비교합니다(`tools/validate_*`).
- 잉크 칩(CSIC) 관련 코드는 모두 **GR 컨트롤러 모듈**(메모리 주소 `0x47C48000`부터)에 있습니다.

## 1. 유지보수통 가상화 — 첫 성공

외부 폐잉크 호스를 쓰기 때문에 유지보수통이 없어도 정상으로 보여야 합니다.

- 상태 API(opcode `0x30`), 조건부 저장, 상태 조회, 카운터 판정 `0x47C63E0C`에서 ARM 명령 6개를 바꿔 "정상, 여유 100%"로 응답하게 했습니다.
- **실기 확인**: 사용자가 정상 동작을 확인했습니다. 이후 모든 버전에 그대로 포함됩니다.
- 문서: `firmware/custom/virtual-maintenance-box-v1/`

## 2. 잉크 칩 1차 시도: 상태값만 덮어쓰기 — 실패

v1(잉크+유지보수), v2(보고 프레임 `0xA80`), v3(오류 합산 `0x104`)에서는 상태 보고만 "정상, 100%"로 바꿨습니다.

- 실제 칩 읽기, 쓰기, 인증은 그대로 남아 있었습니다.
- **실기 결과**: 칩 잔량이 실제로 줄었고, 칩을 빼면 동작하지 않았습니다. 잉크 배출 후 재충전하면 멈췄고, "다음 잉크팩을 인식할 수 없습니다" 문구도 남았습니다.
- 결론: 보고를 바꾸는 것이 아니라 **칩 자체를 펌웨어 안에 만들어야 합니다.**
- 문서: `firmware/custom/virtual-ink-*`, `docs/current-ink-supply-investigation.md`

## 3. 칩 동작 분석

```
칩 버스 읽기/쓰기 (슬롯별 진입점 5개)
   ↓
레지스터 이미지 (슬롯당 168바이트, 비트 단위로 묶인 필드)
   ↓
등록: 전체 스캔 0x47C58AB0 → 슬롯별 등록 0x47C58508 → 인증 → 쓰기 후 다시 읽어 비교하는 자체 시험
   ↓
사용량 기록 0x47C561B4: 계산 → 칩에 기록 → 다시 읽어 확인
   ↓
고유 ID(22바이트)와 사용 이력 비교 0x47D11918 (IC3 플래시의 1WAY0001 이력 영역)
```

- 펌웨어 안에 지원 잉크팩 표(`0x47D39134`, SKU 6종 × 슬롯 4개: 부품 코드, 용량 범위)가 있습니다.
- 칩 필드는 원래 펌웨어의 비트 압축 함수(`0x47C52674` 쓰기, `0x47C522F0` 읽기)로 다룹니다. 용량 해석은 `0x47C55E94`가 합니다.

## 4. 가상 칩 다시 만들기 (V4)

| 구성 요소 | 하는 일 |
|---|---|
| 전송 계층 | 슬롯 0~3의 칩 버스 진입점 5개(`0x47C51B78` 등)를 RAM의 가상 레지스터 버퍼로 돌립니다. 실물 버스는 호출하지 않습니다. |
| 레지스터 이미지 | 펌웨어의 지원 잉크팩 표에서 부품 코드와 용량을 가져와, 원래 펌웨어의 비트 압축 함수로 필드를 채웁니다. |
| SKU | 프린터 속성 `0x2E6`에서 읽어 맞는 표를 고릅니다. |
| 고유 ID | 슬롯마다 바뀌지 않는 가상 ID 4개를 만듭니다. |
| 등록 프로토콜 | 원래 자체 시험(쓰기 후 다시 읽어 비교)을 그대로 통과하게 맞췄습니다. 사용량 감소 시도는 거부하고, 보호된 칸은 유지하고, 다시 읽을 때 수정 표시 비트가 섞이지 않게 했습니다. |
| 인증 | Epson 칩 암호를 흉내 내지 않고, 가상 슬롯을 명시적으로 승인합니다. 검증용 카운터 캐시를 맞추지 않으면 재등록이 오류 `0xAE`로 거부되던 문제도 고쳤습니다. |
| 이력 | 실물 칩 이력을 지우지 않고, 순정의 "이력 없음" 표시값을 씁니다. |
| 표시 | 잔량 표시 바이트만 100%로 고정합니다. 상태, 종류, 오류는 순정 그대로 둡니다. |

에뮬레이터 검증: 전체 스캔 72회, 사용량 기록 144회, 재등록 144회에서 실물 칩 호출은 0회였습니다. 순정 펌웨어는 같은 지점에서 실물 칩 호출에 도달합니다.
문서: `docs/virtual-csic-rewrite-progress.md`

## 5. 부팅 중 전원 꺼짐 — V4, V5 회수

- **실기 결과**: V4는 로고와 진행 표시까지 나온 뒤 전원이 꺼졌습니다. 순정으로 되돌리면 정상이었습니다.
- V5에서 설정 함수의 반환값 오류와, 속성 관리자가 준비되기 전에 속성을 읽는 문제를 고쳤습니다. 가상 칩 활성화도 등록 시점까지 늦췄습니다. **그래도 똑같이 꺼졌습니다.**
- **진짜 원인**: 새 코드를 넣은 `0x47D70000`은 0xFF로 채워져 빈 공간처럼 보였지만, 실제로는 **LCD 화면 버퍼**(480×272×4바이트, `0x47D69594~0x47DE8D94`)였습니다.

```
부팅 → 화면 지우기(0x47C49B40) → 삽입한 코드가 0으로 덮임 → 그 코드를 호출하면 0을 실행 → 멈춤 → 전원 꺼짐
```

원래 코드로 화면 지우기를 실행해서 그대로 재현했습니다. 문서: `docs/virtual-csic-framebuffer-collision.md`

## 6. V6: 코드를 안전한 곳으로 옮김 — 무칩 동작

- 가상 칩이 대신하게 되어 더 이상 쓰이지 않는 순정 칩 인증·호환성 코드 영역(`0x47C57A04~0x47C5824C`, `0x47C8D8D8~0x47C8DA00`)으로 코드를 옮겼습니다.
- 외부 코드가 그 영역 안쪽으로 뛰어드는 분기나 상수 참조가 없는지 전부 검사했습니다. 공개 진입점은 유지합니다.
- 4KB짜리 레지스터 이미지는 214바이트 압축 표로 줄였습니다.
- 화면 버퍼는 순정 바이트로 되돌렸고, 화면 지우기 12회 전후로 코드가 살아 있는지 검사했습니다.
- **실기 확인**: 정상 부팅, 펌프 동작, M 노즐 빠짐 해소, **칩을 빼도 동작**.
- 문서: `firmware/custom/virtual-csic-t3400-candidate-v6/`

## 7. V7: 하프토닝 SML (무칩과 무관)

T3400 Enhanced Matte의 도트 크기 배분(SML 213)을 일반 용지 1200×1200의 SML 214 자리에 넣었습니다.
**실기 결과**: 사용자 PC 드라이버(`EPSON R5690 Series`)로 인쇄했을 때는 눈에 띄는 변화가 없었습니다. 드라이버가 PC에서 하프토닝까지 처리하는지 확인하는 중입니다.
문서: `firmware/custom/matte-sml-candidate-v7/`

## 8. V8: 잉크 "부족" 경고 수정

- **실기 증상**: 칩 없이 쓰는 중에 잔량 막대가 가득 찬 C에 경고(⚠)가 표시되었습니다.
- **원인**: 잔량 상태 판정 `0x47C61B24`는 칩이 아니라 프린터의 색별 누적 사용량 속성(`0x808/0x809/0x80D/0x80E`)을 용량 기준값과 비교합니다. 이 값은 새 잉크팩 ID가 등록될 때만 초기화됩니다(`0x47C58B5C` → `0x47C5BB68(slot,0)`). 가상 ID는 바뀌지 않으므로 사용량이 계속 쌓였고, 그대로 두면 "잉크 소진"으로 인쇄가 멈췄을 것입니다.
- **수정**: 상태 판정 함수가 누적값을 0으로 보게 했습니다(제자리 61바이트 수정). 센서 플래그 `0x47D5EE1C`(`0x47C62038`이 센서를 두 번 확인한 뒤 세움)가 섰을 때의 소진 처리는 그대로 둡니다.
- 실기 확인은 아직입니다. 문서: `firmware/custom/virtual-ink-counter-v8/`, `docs/virtual-ink-counter-fix.json`

## 보조 도구

- 순정 EFU: 업데이트 모드로 되돌릴 때 씁니다(`firmware/original/`).
- EPFWUPD 수정본: PC 업데이터에서 다운그레이드를 허용합니다(`software/firmware-updater/`).
- Adjustment Program 수정본: 유지보수통 카운터를 초기화할 수 있게 했습니다(`software/adjustment-program/`).
- EEPROM 분석: 초기 충전 플래그, 청소 플래그, 누수 리셋 항목을 찾아 주소표로 정리했습니다(`firmware/nvram/`).

## 남은 한계

- Epson 칩 암호를 재현한 것이 아니라, 펌웨어 쪽에서 가상 칩을 승인하는 방식입니다.
- 누적 사용량은 저장 공간에 계속 쌓입니다. 장기간 사용했을 때의 영향은 아직 모릅니다.
- 빈 팩 감지는 물리 센서 경로에만 의존합니다. 그 플래그가 잉크 센서라는 것도 코드 동작으로 추정한 것입니다.
- 장기 안정성은 사용자 실사용으로만 확인되고 있습니다.
